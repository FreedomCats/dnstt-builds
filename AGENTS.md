# Правила проекта для агентов

## Что это

Неофициальные сборки [dnstt](https://www.bamsoftware.com/software/dnstt/) (David Fifield,
CC0). Исходники dnstt здесь не хранятся: их берёт CI из зеркала организации
`FreedomCats/dnstt` по тегу апстрима, сверяет с записанным здесь хешем коммита, собирает и
публикует релиз. Релизы — только вручную (`workflow_dispatch`). Собирается только `master`
апстрима (его теги); ветки апстрима (`utls`, `any-domain`) не собираются.

Свой код (workflow, скрипты, README) — под CC0, как dnstt.

## Личные данные — никогда в репозиторий

**Это вопрос безопасности разработчика, а не аккуратности.** Если разработчика
вычислят, это угрожает его жизни, здоровью и свободе. Поэтому в репозиторий не
должно попадать ничего, что позволяет его опознать: настоящее имя, почта,
IP-адреса, имена аккаунтов, организация, где он работает, детали рабочего окружения и
ОС, имя пользователя — и вообще любая деталь, по которой его легко найти. При
сомнении — не записывать.

Репозиторий публичный. В документацию, код, комментарии, сообщения коммитов и в
публикуемые артефакты (бинари, архивы, описания релизов) **нельзя** записывать:

- настоящее имя пользователя, его почты, имена его личных аккаунтов GitHub и других,
  работодателя;
- окружение разработчика: дистрибутив и машину, имя пользователя, домашние каталоги
  (`/home/…`, `C:\Users\…`), рабочие сети, адреса;
- даты и время работы: когда что сделано или проверено;
- пароли, ключи, токены.

Вместо них — слова или заглушки: пользователь `user`, `192.0.2.x`, `2001:db8::`.

Показывать эти значения пользователю в чате можно. В файлы репозитория — нет.

Публикуемые бинари собирает **только CI**. Локальные сборки — для проверки, их не
публикуют: в них может попасть окружение машины.

## Документы

`doc/local/` — вне git: журнал работы, записка для продолжения, черновики с окружением.
Всё остальное публикуется и подчиняется правилам выше.

## Коммиты

Автор и коммиттер — только `FreedomCats <noreply@freedomcats.invalid>` (задано в
`.git/config` репозитория). Дата — сегодняшняя, но без времени: полночь UTC.

    d=$(date +%F)T00:00:00Z
    GIT_AUTHOR_DATE=$d GIT_COMMITTER_DATE=$d git commit …

То же при `--amend`, `rebase` и `cherry-pick`. Теги — только лёгкие (`git tag v…`, без
`-a`, `-s`, `-m`). В сообщениях коммитов — без строки `Claude-Session: …`, только
`Co-Authored-By`; номера задач Jira не нужны.

**Перед каждым коммитом** проверить `git diff --cached` на всё перечисленное выше. После
коммита — `git log -1 --format='%an <%ae> %ad | %cn <%ce> %cd' --date=iso-strict`.

Пушить, создавать репозиторий на GitHub, запускать релиз — только по просьбе
пользователя.
